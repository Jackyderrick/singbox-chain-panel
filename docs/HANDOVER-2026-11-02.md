## 1. 项目职责

这是一个单机 `sing-box` 管理面板，用于管理 VLESS Reality 入站、客户、设备链接、有效期、累计流量及多个 SOCKS5 家宽出口。

- 后端：Python 标准库，入口为 `panel.py`
- 代理核心：`sing-box`
- 面板：默认监听 `127.0.0.1:8080`，由 Nginx 反代
- 状态存储：`/opt/singbox-panel/state.json`
- sing-box 主配置：`/etc/sing-box/config.json`

项目不包含数据库、多管理员权限、支付订阅或真实硬件级设备识别。设备数限制按最近来源 IP 近似判断。

## 5. 配置与数据边界

### 可安全查看

```bash
sudo systemctl status sing-box singbox-panel nginx singbox-watchdog --no-pager -l
sudo sing-box check -c /etc/sing-box/config.json
sudo ss -ltnp | grep -E ':(22|80|443|8080|9090)\b'
sudo journalctl -u sing-box -u singbox-panel -n 100 --no-pager
sudo python3 -m py_compile /opt/singbox-panel/panel.py
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/
```

### 重要数据

- `state.json`：客户、设备 UUID、有效期、累计流量、家宽出口凭据等。删除会丢失业务数据。
- `config.json`：VLESS 用户、Reality 入站、SOCKS5 出站和客户分流规则。手改前务必备份。
- `backups/`：面板每次改写 `config.json` 前的备份；不要随意清空。
- `/etc/singbox-panel.env`：面板密码、签名密钥、节点域名、Reality 公钥等敏感环境变量；权限应限制为 root 可读。

预期：四个服务均为 `active`，面板本地/公网状态码为 `200`，`sing-box check` 通过，443/8080/9090 均有监听。

## 7. 常用运维操作

### 查看日志

```bash
sudo journalctl -u singbox-panel -f
sudo journalctl -u sing-box -f
sudo journalctl -u singbox-watchdog -f
```

### 仅在确认需要时执行

```bash
sudo systemctl restart singbox-panel
sudo systemctl restart nginx
sudo systemctl restart sing-box
```

`restart sing-box` 会断开所有现有代理连接；添加/删除客户、设备或家宽出口时，面板也会修改配置并重启 sing-box。操作前应告知在用客户。

### 回滚 sing-box 配置

```bash
sudo ls -lt /opt/singbox-panel/backups/
sudo cp /opt/singbox-panel/backups/config-YYYYmmdd-HHMMSS.json /etc/sing-box/config.json
sudo sing-box check -c /etc/sing-box/config.json
sudo systemctl restart sing-box
```

先将示例文件名替换为实际备份。不要在未通过 `sing-box check` 的情况下重启服务。

## 8. 已知运行约束

- 服务器为共享 `1 vCPU`。历史上出现过持续高 CPU 后平台保护性关机/限频；不要提高频繁轮询、批量测速或并发重启频率。
- 已配置/计划的资源限制目标：`sing-box` 约 22% CPU，面板约 4%，Nginx 约 4%，watchdog 约 1%。实际值须以 systemd unit 文件为准。
- VLESS 节点域名不能启用 Cloudflare 橙云代理；面板域名可以通过 Cloudflare 代理。
- 客户端出现 `flow mismatch`，通常是导入链接丢失 `flow=xtls-rprx-vision` 或客户端不兼容；这不必然表示服务器故障。
- SOCKS5 出口是否可访问特定网站、可用带宽和是否限流由家宽提供方决定；面板只负责验证连接和配置路由。
- 当前本地电脑未获得公网 IPv6 和 IPv6 默认路由，不能作为 IPv6 SSH 巡检来源。服务器 IPv6 是否可达需从具备 IPv6 出口的网络验证。

## 9. 安全与交接清单

接管后优先完成：

1. 轮换 root 密码、面板密码、`PANEL_SECRET`、SOCKS5 凭据和可能泄露的 Reality 密钥。
2. 备份 `/etc/sing-box/config.json`、`/opt/singbox-panel/state.json`、`/opt/singbox-panel/backups/` 与相关 systemd/Nginx 配置到加密存储。
3. 确认防火墙仅开放 `22`、`80`、`443`；不要把 `8080`、`9090` 暴露到公网。
4. 为 root SSH 设置密钥登录，并在验证成功后关闭密码登录。
5. 每次改动前执行 `sing-box check`，每次改动后用一个测试链接验证 443 入站及预期 SOCKS5 出口。
6. 将 `state.json` 与 `config.json` 一并备份；单独还原其中一个文件可能造成面板记录与 sing-box 用户不一致。

## 10. 恢复优先级

当“面板可开但节点不可用”时，依序检查：

```bash
sudo systemctl status sing-box --no-pager -l
sudo sing-box check -c /etc/sing-box/config.json
sudo ss -ltnp | grep ':443'
sudo journalctl -u sing-box -n 100 --no-pager
```

当“域名面板打不开”时，依序检查：

```bash
sudo systemctl status nginx singbox-panel --no-pager -l
curl -i http://127.0.0.1:8080/
sudo nginx -t
sudo journalctl -u nginx -u singbox-panel -n 100 --no-pager
```

当“所有服务失联”时，先在云厂商控制台确认实例开机、CPU 没有被保护性关机、IPv4/IPv6 仍被分配、安全组仍放行 TCP 22；随后再通过 SSH 进入主机巡检。
